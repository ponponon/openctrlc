---
title: Sharing
description: Configure optional conversation sharing in OpenCtrlC.
---

OpenCtrlC can integrate with a compatible sharing service, but the public
OpenCtrlC website does not provide a hosted sharing backend. Sharing is
therefore opt-in and should stay disabled unless you have configured and
reviewed the destination yourself.

:::caution
Shared conversations may contain source code, prompts, command output, and
model responses. Treat every shared link as public to anyone who has it.
:::

## Disable sharing

Use this setting for normal local development and for projects that have not
approved a sharing service:

```json title="openctrlc.json"
{
  "$schema": "https://openctrlc.pages.dev/config.json",
  "share": "disabled"
}
```

You can also set `OPENCTRLC_DISABLE_SHARE=1` in the environment to disable the
feature for a process.

## Self-managed sharing

If your organization operates a compatible sharing backend, configure its URL
through the enterprise/server integration documented for your deployment. The
backend is responsible for authentication, retention, deletion, and access
control. Review the implementation before enabling `manual` or `auto` sharing.

## Before sharing

- Remove API keys, tokens, passwords, and proprietary source code.
- Review the complete conversation and tool output.
- Prefer `manual` mode when sharing is approved but should be deliberate.
- Use `auto` only when every conversation in the project may be sent to the
  configured service.
- Delete shared data when collaboration is complete.
