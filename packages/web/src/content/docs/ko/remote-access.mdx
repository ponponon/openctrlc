OpenCtrlC Desktop은 OpenCtrlC Remote Relay를 통해 현재 로컬 작업 공간을 휴대폰에서 열 수 있습니다. 데스크톱이 릴레이에 아웃바운드로 연결되므로 PC의 인바운드 포트를 공개하거나 웹 서버를 직접 시작할 필요가 없습니다.

## 휴대폰 연결

1. 데스크톱 사이드바 또는 제목 표시줄의 휴대폰 아이콘을 엽니다.
2. **휴대폰 액세스 켜기**를 선택하고 휴대폰으로 QR 코드를 스캔합니다.
3. 데스크톱에서 해당 기기를 승인합니다. QR 링크는 전달될 수 있고 브라우저 표시는 참고용이므로, 지금 페어링하는 기기만 승인하세요. QR 링크만으로는 작업 공간에 접속할 수 없습니다.
4. 휴대폰에서 사용하는 동안 데스크톱 앱을 계속 실행해 둡니다.

페어링 링크는 데스크톱 세션이 활성화된 동안에만 사용할 수 있습니다. 각 브라우저는 처음 한 번 승인을 받아야 하며, 이후 모바일 액세스가 켜져 있는 동안 다시 연결할 수 있습니다. 30일 동안 사용하지 않으면 승인이 만료되고, 작업 공간을 사용하면 자동으로 연장됩니다. 세션당 기본 승인 한도는 브라우저 10개이며, 데스크톱 액세스 창에서 1~100개로 설정할 수 있습니다. 한도를 낮춰도 기존 승인은 취소되지 않지만, 승인된 브라우저 수가 한도보다 적어질 때까지 새 브라우저를 승인할 수 없습니다. 데스크톱의 승인된 브라우저 목록에서 하나씩 승인을 취소하면서 다른 브라우저의 연결은 유지할 수 있습니다. 브라우저 표시는 참고 정보일 뿐 실제 기기를 인증하지 않습니다. QR 코드를 새로 고치면 대기 중인 승인 요청이 취소됩니다. **휴대폰 액세스 중지**를 선택하면 승인된 브라우저가 모두 취소됩니다. 데스크톱 앱을 종료하거나 다시 시작해도 세션은 유지되며 승인된 브라우저의 권한은 사라지지 않습니다. 모바일 액세스를 다시 켜면 재스캔 없이 바로 다시 연결할 수 있습니다. 데스크톱의 Relay 연결이 예기치 않게 끊기면 기존 세션을 자동 복구하며, 이 시간에는 브라우저 승인이 유지됩니다. 승인된 브라우저가 있는 세션은 브라우저 승인 30일 유효 기간과 동일하게 최대 30일 동안 복구할 수 있습니다. 승인된 브라우저가 없는 세션은 1시간 후 정리됩니다. Relay가 재시작되거나 복구 시간이 끝나면 세션이 종료되므로 모바일 액세스를 다시 켜고 새 QR 코드를 스캔해야 합니다.

## 네트워크와 개인정보

데스크톱과 휴대폰은 WSS/HTTPS로 릴레이와 통신하며 직접 연결할 수 없을 때는 릴레이를 통해 데이터를 전송합니다. 릴레이는 HTTP 스트림과 WebSocket 트래픽을 데스크톱의 루프백 서버로 전달합니다. PC로 들어오는 연결을 열지 않으며 이 구성은 요청 액세스 로그를 비활성화합니다. 프롬프트, 메시지 본문, 파일 내용은 의도적으로 저장하지 않습니다. 릴레이 영구 저장을 사용 설정하면 복구 파일에 세션 재개 자격 증명, 브라우저 승인, 작업 공간 메타데이터가 저장됩니다.

새로 페어링한 브라우저에서 데스크톱의 현재 작업 공간을 복원하기 위해 릴레이는 열린 프로젝트 경로, 세션 ID, 현재 세션 ID를 메모리에 보관합니다. 영구 저장이 사용 설정되어 있으면 세션이 중지되거나 만료될 때까지 접근이 제한된 복구 파일에도 저장됩니다. 이 인덱스는 승인된 브라우저에만 전송되며 프롬프트, 초안, 메시지 본문은 포함하지 않습니다. 프로젝트 경로와 세션 ID는 민감한 메타데이터이며 릴레이 운영자가 볼 수 있습니다.

WSS/HTTPS 경로의 각 구간은 TLS로 보호되지만 종단 간 암호화는 아닙니다. 릴레이는 전달 중 트래픽을 복호화하므로 운영자가 전송 중인 콘텐츠를 기술적으로 확인할 수 있습니다. 릴레이가 지원되는 P2P 프로토콜을 알리고 ICE 서버가 설정되어 있으면 데스크톱과 브라우저가 WebRTC DataChannel로 직접 데이터를 전송할 수 있습니다. 이 경로는 DTLS를 사용하며 데이터가 릴레이를 통과하지 않습니다. 시그널링과 ICE 후보는 계속 릴레이를 통과하고, 두 피어가 서로의 네트워크 주소를 알게 될 수 있습니다. 악의적인 릴레이가 시그널링을 변조하는 경우에는 보호되지 않습니다. P2P를 지원하지 않거나 연결에 실패하면 WSS/HTTPS 릴레이 경로를 사용합니다. 사용하기 전에 릴레이 운영자를 신뢰할 수 있는지 확인하세요. 데스크톱의 로컬 서버 자격 증명은 데스크톱에만 보관되며 휴대폰으로 보내지 않습니다.

`openctrlc-remote.quniv.cn`의 공개 릴레이는 현재 단일 인스턴스의 제한된 용량으로 운영됩니다. 속도와 가용성은 릴레이 지역과 대역폭에 따라 달라집니다. 릴레이 소스 코드와 배포 예제는 [`packages/remote-relay`](https://github.com/ponponon/openctrlc/tree/dev/packages/remote-relay)에 있습니다. 신뢰하는 지역에서 직접 릴레이를 운영할 수도 있습니다.

## 릴레이 운영

Docker Compose 및 OpenResty 구성은 [릴레이 README](https://github.com/ponponon/openctrlc/tree/dev/packages/remote-relay)를 참고하세요. 공개 HTTPS 호스트 이름, WebSocket 업그레이드, 장시간 스트리밍 타임아웃, 신뢰할 수 있는 TLS 인증서가 필요합니다. 단일 인스턴스를 재시작하면 기존 연결과 처리 중인 요청이 끊깁니다. 영구 데이터 디렉터리를 설정한 경우 릴레이는 재개 가능한 세션과 브라우저 승인을 복구하므로 데스크톱이 다시 연결할 수 있습니다. 처리 중인 스트림은 복구되지 않습니다.
