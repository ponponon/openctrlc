OpenCtrlC Desktop은 OpenCtrlC Remote Relay를 통해 현재 로컬 작업 공간을 휴대폰에서 열 수 있습니다. 데스크톱이 릴레이에 아웃바운드로 연결되므로 PC의 인바운드 포트를 공개하거나 웹 서버를 직접 시작할 필요가 없습니다.

## 휴대폰 연결

1. 데스크톱 사이드바 또는 제목 표시줄의 휴대폰 아이콘을 엽니다.
2. **휴대폰 액세스 켜기**를 선택하고 휴대폰으로 QR 코드를 스캔합니다.
3. 데스크톱에서 해당 기기를 승인합니다. QR 링크는 전달될 수 있고 브라우저 표시는 참고용이므로, 지금 페어링하는 기기만 승인하세요. QR 링크만으로는 작업 공간에 접속할 수 없습니다.
4. 휴대폰에서 사용하는 동안 데스크톱 앱을 계속 실행해 둡니다.

페어링 링크는 데스크톱 세션이 활성화된 동안에만 사용할 수 있습니다. 각 브라우저는 처음 한 번 승인을 받아야 하며, 이후 모바일 액세스가 켜져 있는 동안 다시 연결할 수 있습니다. 30일 동안 사용하지 않으면 승인이 만료되고, 작업 공간을 사용하면 자동으로 연장됩니다. 동시에 최대 3개의 브라우저를 승인할 수 있습니다. QR 코드를 새로 고치면 대기 중인 승인 요청이 취소됩니다. **휴대폰 액세스 중지**를 선택하면 승인된 브라우저가 모두 취소되며, 데스크톱 앱을 종료해도 세션이 끝납니다.

## 네트워크와 개인정보

데스크톱과 휴대폰은 WSS/HTTPS로 릴레이에 연결합니다. 릴레이는 HTTP 스트림과 WebSocket 트래픽을 데스크톱의 루프백 서버로 전달합니다. PC로 들어오는 연결을 열지 않으며 이 구성은 요청 액세스 로그를 비활성화합니다. 작업 공간 콘텐츠는 메모리에서 처리되며 의도적으로 영구 저장하지 않습니다.

TLS는 각 네트워크 구간을 보호하지만 종단 간 암호화는 아닙니다. 릴레이는 전달 중 트래픽을 복호화하므로 운영자가 전송 중인 콘텐츠를 기술적으로 확인할 수 있습니다. 사용하기 전에 릴레이 운영자를 신뢰할 수 있는지 확인하세요. 데스크톱의 로컬 서버 자격 증명은 데스크톱에만 보관되며 휴대폰으로 보내지 않습니다.

`openctrlc-remote.quniv.cn`의 공개 릴레이는 현재 단일 인스턴스의 제한된 용량으로 운영됩니다. 속도와 가용성은 릴레이 지역과 대역폭에 따라 달라집니다. 릴레이 소스 코드와 배포 예제는 [`packages/remote-relay`](https://github.com/ponponon/openctrlc/tree/dev/packages/remote-relay)에 있습니다. 신뢰하는 지역에서 직접 릴레이를 운영할 수도 있습니다.

## 릴레이 운영

Docker Compose 및 OpenResty 구성은 [릴레이 README](https://github.com/ponponon/openctrlc/tree/dev/packages/remote-relay)를 참고하세요. 공개 HTTPS 호스트 이름, WebSocket 업그레이드, 장시간 스트리밍 타임아웃, 신뢰할 수 있는 TLS 인증서가 필요합니다. 세션 상태는 메모리에만 보관되므로 단일 인스턴스를 재시작하면 연결된 데스크톱과 휴대폰의 연결이 끊깁니다.
