---
title: 手机远程访问
description: 通过二维码配对和桌面端批准，在手机上打开桌面工作区。
---

OpenCtrlC 桌面版可以通过 OpenCtrlC Remote Relay 将当前本地工作区提供给手机访问。桌面端主动连接中继，因此无需在电脑上开放入站端口，也不必手动启动 Web 服务器。

## 连接手机

1. 点击桌面版侧边栏或标题栏中的手机图标，打开手机访问面板。
2. 选择**开启手机访问**，再用手机扫描二维码。
3. 在桌面版批准这台手机。二维码链接可能被转发，浏览器标识也仅供参考；只批准你正在配对的设备。只有二维码链接并不能进入工作区。
4. 使用期间保持桌面应用运行。

配对链接仅在桌面会话有效期间可用。每个浏览器首次连接时需要批准，之后只要手机访问保持开启就可以直接重连。授权会在连续 30 天未使用后过期，使用工作区时会自动续期。每个会话默认最多允许 10 个已授权浏览器；你可以在桌面端手机访问窗口中自定义为 1–100 个。调低上限不会撤销已有授权，但已授权数量低于上限前不能再批准新浏览器。你可以在桌面端已授权浏览器列表中单独撤销某个浏览器，同时保留其他浏览器的访问；浏览器标识仅供参考，不能验证真实设备身份。刷新二维码会取消待批准请求。选择**停止手机访问**会撤销所有已授权浏览器。关闭或重启桌面应用不会结束会话，已批准浏览器的授权会保留；手机访问再次开启后可以直接重连，无需重新扫码。桌面端意外失去中继连接时会自动恢复原会话，期间保留已批准浏览器的授权。带已授权浏览器的会话最长可恢复 30 天，与浏览器授权有效期一致；没有授权浏览器的会话会在 1 小时后清理。中继重启或恢复窗口到期后，会话结束，需要重新开启手机访问并扫描新二维码。

## 网络与隐私

桌面端和手机通过 WSS/HTTPS 与中继协调；直连不可用时，流量也会经由中继传输。中继把 HTTP 数据流和 WebSocket 流量转发到桌面端的本地服务器，不会向你的电脑发起入站连接；此部署关闭了请求访问日志。提示词、消息正文和文件内容不会被主动持久化。启用中继持久化时，恢复文件会保存会话恢复凭据、浏览器授权和工作区元数据。

为了让新配对的浏览器恢复桌面端当前工作区，中继会在内存中保存已打开的项目路径、会话 ID 和当前会话 ID；启用持久化时，这些信息也会写入受限访问的恢复文件，直到会话停止或过期。该索引只发送给已授权浏览器，不包含提示词、草稿或消息正文。项目路径和会话 ID 属于敏感元数据，中继运营方可以看到。

WSS/HTTPS 中继链路由 TLS 保护，但这不是端到端加密：中继会在转发时解密流量，因此中继运营方在技术上可以查看传输中的内容。如果中继公布了受支持的 P2P 协议并配置了 ICE 服务器，桌面端和浏览器可以尝试通过 WebRTC DataChannel 直连传输数据；该链路使用 DTLS，数据不会经过中继。信令和 ICE 候选地址仍会经过中继，两个端点也可能获知对方的网络地址；如果中继恶意篡改信令，这种方式无法防范。P2P 不受支持或连接失败时，流量继续走 WSS/HTTPS 中继。开启前请确认你信任中继运营方。桌面端的本地服务器凭据保留在桌面，不会发送给手机。

`openctrlc-remote.quniv.cn` 上的公共中继目前是单实例、有限容量的部署。速度和可用性取决于中继所在地区和带宽。中继源码与部署示例位于 [`packages/remote-relay`](https://github.com/ponponon/openctrlc/tree/dev/packages/remote-relay)，团队也可以在信任的地区自行部署。

## 部署中继

参阅[中继服务 README](https://github.com/ponponon/openctrlc/tree/dev/packages/remote-relay)了解 Docker Compose 和 OpenResty 配置。部署需要一个公网 HTTPS 域名、WebSocket 升级支持、足够长的流式连接超时和可信 TLS 证书。重启单实例会断开现有连接和处理中请求。配置持久化数据目录后，中继会恢复可续接的会话和浏览器授权，桌面端可重新连接；正在传输的请求和流无法恢复。
