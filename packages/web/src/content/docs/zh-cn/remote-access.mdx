---
title: 手机远程访问
description: 通过二维码配对和桌面端批准，在手机上打开桌面工作区。
---

OpenCtrlC 桌面版可以通过 OpenCtrlC Remote Relay 将当前本地工作区提供给手机访问。桌面端主动连接中继，因此无需在电脑上开放入站端口，也不必手动启动 Web 服务器。

## 连接手机

1. 点击桌面版侧边栏或标题栏中的手机图标，打开手机访问面板。
2. 选择**开启手机访问**，再用手机扫描二维码。
3. 在桌面版批准这台手机。二维码链接可能被转发，浏览器标识也仅供参考；只批准你正在配对的设备。只有二维码链接并不能进入工作区。
4. 使用期间保持桌面应用运行。

配对链接仅在桌面会话有效期间可用。每个浏览器首次连接时需要批准，之后只要手机访问保持开启就可以直接重连。授权会在连续 30 天未使用后过期，使用工作区时会自动续期。同时最多允许三个已授权浏览器。你可以在桌面端已授权浏览器列表中单独撤销某个浏览器，同时保留其他浏览器的访问；浏览器标识仅供参考，不能验证真实设备身份。刷新二维码会取消待批准请求。选择**停止手机访问**会撤销所有已授权浏览器；关闭桌面应用也会结束会话。桌面端意外失去中继连接时，会在最多 3 分钟内自动恢复原会话，期间保留已批准浏览器的授权。这是网络故障恢复窗口，与浏览器授权的 30 天有效期无关。中继重启或恢复窗口到期后，会话结束，需要重新开启手机访问并扫描新二维码。

## 网络与隐私

桌面端和手机通过 WSS/HTTPS 连接中继。中继把 HTTP 数据流和 WebSocket 流量转发到桌面端的本地服务器，不会向你的电脑发起入站连接；此部署关闭了请求访问日志。工作区内容只在内存中处理，不会被主动持久化。

TLS 保护网络传输链路，但这不是端到端加密：中继会在转发时解密流量，因此中继运营方在技术上可以查看传输中的内容。开启前请确认你信任中继运营方。桌面端的本地服务器凭据保留在桌面，不会发送给手机。

`openctrlc-remote.quniv.cn` 上的公共中继目前是单实例、有限容量的部署。速度和可用性取决于中继所在地区和带宽。中继源码与部署示例位于 [`packages/remote-relay`](https://github.com/ponponon/openctrlc/tree/dev/packages/remote-relay)，团队也可以在信任的地区自行部署。

## 部署中继

参阅[中继服务 README](https://github.com/ponponon/openctrlc/tree/dev/packages/remote-relay)了解 Docker Compose 和 OpenResty 配置。部署需要一个公网 HTTPS 域名、WebSocket 升级支持、足够长的流式连接超时和可信 TLS 证书。中继会把会话状态保存在内存中；重启单实例会断开已连接的桌面和手机。
