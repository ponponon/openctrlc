[**OpenCtrlC**](/) 是一个专注于终端工作流和本地开发的开源 AI 编码代理。

让我们开始吧。

---

#### 前提条件

要在终端中使用 OpenCtrlC，你需要：

1. 一款现代终端模拟器，例如：
   - [WezTerm](https://wezterm.org)，跨平台
   - [Alacritty](https://alacritty.org)，跨平台
   - [Ghostty](https://ghostty.org)，Linux 和 macOS
   - [Kitty](https://sw.kovidgoyal.net/kitty/)，Linux 和 macOS

2. 你想使用的 LLM 提供商的 API 密钥。

---

## 安装

安装 OpenCtrlC 最简单的方法是通过安装脚本。

```bash
curl -fsSL https://raw.githubusercontent.com/ponponon/openctrlc/dev/install | bash
```

针对不同平台，可以从[官网软件下载页](https://openctrlc.pages.dev/download/)下载最新安装包；
稳定版在可用时优先使用 R2 镜像，失败时自动回退到 [GitHub Releases](https://github.com/ponponon/openctrlc/releases)。

---

## 配置

通过 OpenCtrlC，你可以配置 API 密钥来使用受支持的 LLM 提供商。
OpenCtrlC 不提供托管模型服务，你可以自行选择提供商和计费方式。

1. 在 TUI 中运行 `/connect` 命令，选择一个 LLM 提供商，并按照[提供商文档](/docs/providers)完成配置。

   ```txt
   /connect
   ```

2. 按照提供商的指引完成登录或配置，然后复制 API 密钥。

3. 粘贴你的 API 密钥。

   ```txt
   ┌ API key
   │
   │
   └ enter
   ```

你可以随时更换提供商。[查看提供商目录](/docs/providers#directory)。

---

## 初始化

配置好提供商后，导航到你想要处理的项目目录。

```bash
cd /path/to/project
```

然后运行 OpenCtrlC。

```bash
openctrlc
```

接下来，运行以下命令为项目初始化 OpenCtrlC。

```bash frame="none"
/init
```

OpenCtrlC 会分析你的项目并在项目根目录创建一个 `AGENTS.md` 文件。

:::tip
你应该将项目的 `AGENTS.md` 文件提交到 Git。
:::

这有助于 OpenCtrlC 理解项目结构和编码规范。

## 使用

现在你已经准备好使用 OpenCtrlC 来处理项目了，尽管提问吧！

如果你是第一次使用 AI 编码代理，以下示例可能会对你有所帮助。

---

### 提问

你可以让 OpenCtrlC 为你讲解代码库。

:::tip
使用 `@` 键可以模糊搜索项目中的文件。
:::

```txt frame="none" "@packages/opencode/src/session/prompt.ts"
@packages/opencode/src/session/prompt.ts 中的提示词 admission 是如何工作的？
```

当你遇到不熟悉的代码时，这个功能非常有用。

---

### 添加功能

你可以让 OpenCtrlC 为项目添加新功能。不过我们建议先让它制定一个计划。

1. **制定计划**

   OpenCtrlC 有一个*计划模式*，该模式下它不会进行任何修改，而是建议*如何*实现该功能。

   使用 **Tab** 键切换到计划模式。你会在右下角看到模式指示器。

   ```bash frame="none" title="Switch to Plan mode"
   <TAB>
   ```

   接下来描述你希望它做什么。

   ```txt frame="none"
   当提示词被 admission 后，我们希望为会话记录一条诊断事件。
   请先追踪现有的提示词和会话事件流程，再提出保持当前持久化行为的最小实现方案。
   ```

   你需要提供足够的细节，让 OpenCtrlC 理解你的需求。可以把它当作团队中的一名初级开发者来沟通。

   :::tip
   为 OpenCtrlC 提供充足的上下文和示例，帮助它理解你的需求。
   :::

2. **迭代计划**

   当它给出计划后，你可以提供反馈或补充更多细节。

   ```txt frame="none"
   We'd like to design this new screen using a design I've used before.
   [Image #1] Take a look at this image and use it as a reference.
   ```

   :::tip
   将图片拖放到终端中即可将其添加到提示词中。
   :::

   OpenCtrlC 可以扫描你提供的图片并将其添加到提示词中。只需将图片拖放到终端窗口即可。

3. **构建功能**

   当你对计划满意后，再次按 **Tab** 键切换回*构建模式*。

   ```bash frame="none"
   <TAB>
   ```

   然后让它开始实施。

   ```bash frame="none"
   Sounds good! Go ahead and make the changes.
   ```

---

### 直接修改

对于比较简单的修改，你可以直接让 OpenCtrlC 实施，无需先审查计划。

```txt frame="none" "@packages/opencode/src/session/processor.ts" "@packages/opencode/src/session/prompt.ts"
请追踪已 admission 的提示词如何进入 session processor，说明持久化提示词 admission
与模型执行之间的边界，并提出一个不重复实现会话编排的聚焦改动。
```

请确保提供足够的细节，以便 OpenCtrlC 做出正确的修改。

---

### 撤销修改

假设你让 OpenCtrlC 做了一些修改。

```txt frame="none" "@packages/opencode/src/session/processor.ts"
请重构 @packages/opencode/src/session/processor.ts 中的 session processor。
```

但你发现结果不是你想要的。你**可以使用** `/undo` 命令来撤销修改。

```bash frame="none"
/undo
```

OpenCtrlC 会还原所做的修改，并重新显示你之前的消息。

```txt frame="none" "@packages/opencode/src/session/processor.ts"
请重构 @packages/opencode/src/session/processor.ts 中的 session processor。
```

你可以调整提示词，让 OpenCtrlC 重新尝试。

:::tip
你可以多次运行 `/undo` 来撤销多次修改。
:::

你也**可以使用** `/redo` 命令来重做修改。

```bash frame="none"
/redo
```

## 分享

你与 OpenCtrlC 的对话可以[与团队分享](/docs/share)。

```bash frame="none"
/share
```

这会生成当前对话的链接并复制到剪贴板。

:::note
对话默认不会被分享。
:::

你可以使用 `/share` 命令与团队分享会话。
