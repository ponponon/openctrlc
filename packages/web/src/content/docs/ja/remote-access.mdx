title: モバイルからのリモートアクセス
description: QR コードでペアリングし、デスクトップで承認してスマートフォンからワークスペースを開きます。
---

OpenCtrlC Desktop は OpenCtrlC Remote Relay を経由して、現在のローカルワークスペースをスマートフォンから開けます。デスクトップから中継サーバーへ接続するため、PC の受信ポートを公開したり、Web サーバーを手動で起動したりする必要はありません。

## スマートフォンを接続する

1. デスクトップのサイドバーまたはタイトルバーにあるスマートフォンアイコンを開きます。
2. **モバイルアクセスを有効にする**を選び、スマートフォンで QR コードをスキャンします。
3. デスクトップでその端末を承認します。QR コードのリンクは転送される可能性があり、表示されるブラウザー情報は目安です。今ペアリングしている端末だけを承認してください。リンクだけではワークスペースに接続できません。
4. スマートフォンで使用している間はデスクトップアプリを起動したままにします。

ペアリングリンクはデスクトップセッションが有効な間だけ使えます。各ブラウザーは最初に一度承認が必要です。その後はモバイルアクセス中に再接続できます。30 日間使われないと承認が期限切れになり、ワークスペースを使うと自動で延長されます。1 セッションあたりの初期上限は 10 台で、デスクトップのアクセス画面から 1～100 台に変更できます。上限を下げても既存の許可は取り消されませんが、許可済みの数が上限を下回るまで新しいブラウザーを許可できません。デスクトップの承認済みブラウザー一覧から一つずつ許可を取り消し、ほかのブラウザーの接続を保つこともできます。ブラウザー情報は参考であり、実際の端末を認証するものではありません。QR コードを更新すると、保留中の承認リクエストが取り消されます。**モバイルアクセスを停止**すると承認済みのブラウザーがすべて無効になります。デスクトップアプリを終了または再起動してもセッションは維持され、承認済みブラウザーの許可は失われません。モバイルアクセスが再び有効になれば、再スキャンなしで再接続できます。デスクトップの Relay 接続が予期せず切れた場合も元のセッションを自動で復元し、その間はブラウザーの承認を保持します。承認済みブラウザーがあるセッションは最大 30 日間復元可能で、ブラウザー承認の有効期間と一致します。承認済みブラウザーがないセッションは 1 時間後に清理されます。Relay の再起動または復旧時間の終了後はセッションが終了するため、モバイルアクセスを再度有効にして新しい QR コードをスキャンしてください。

## ネットワークとプライバシー

デスクトップとスマートフォンは WSS/HTTPS で中継サーバーに接続します。中継サーバーは HTTP ストリームと WebSocket 通信をデスクトップのループバックサーバーへ転送します。PC への受信接続は開かず、この構成ではリクエストのアクセスログを無効にしています。ワークスペースの内容はメモリ上で処理され、意図的には永続化されません。

新しくペアリングしたブラウザーでデスクトップの現在のワークスペースを復元するため、中継サーバーは開いているプロジェクトのパス、セッション ID、アクティブなセッション ID を一時的にメモリに保持し、承認済みブラウザーだけに送信します。このインデックスにプロンプト、下書き、メッセージ本文は含まれません。プロジェクトのパスとセッション ID は機密性のあるメタデータであり、セッション中は中継サーバーの運営者が確認できます。

TLS は各ネットワーク区間を保護しますが、エンドツーエンド暗号化ではありません。中継サーバーは転送中に通信を復号するため、運営者は技術的に内容を確認できます。有効にする前に中継サーバーの運営者を信頼できることを確認してください。デスクトップのローカルサーバー認証情報はデスクトップに保持され、スマートフォンには送信されません。

`openctrlc-remote.quniv.cn` の公開中継サーバーは、現在単一インスタンスの限定的な構成です。速度と稼働状況はサーバーの地域と帯域幅によって異なります。中継サーバーのソースコードとデプロイ例は [`packages/remote-relay`](https://github.com/ponponon/openctrlc/tree/dev/packages/remote-relay) にあります。信頼できる地域で独自の中継サーバーを運用できます。

## 中継サーバーの運用

Docker Compose と OpenResty の設定は[中継サーバーの README](https://github.com/ponponon/openctrlc/tree/dev/packages/remote-relay)を参照してください。公開 HTTPS ドメイン、WebSocket アップグレード、長時間のストリーミング接続タイムアウト、信頼できる TLS 証明書が必要です。セッション状態はメモリ上に保持されるため、単一インスタンスを再起動すると接続中のデスクトップとスマートフォンは切断されます。
