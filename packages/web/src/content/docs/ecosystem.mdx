OpenCtrlC is designed to work with the tools you already use. Its local CLI,
desktop application, HTTP API, SDK, skills, and GitHub Action can be composed
into workflows without a hosted OpenCtrlC account.

## Official building blocks

- **CLI and desktop app** — run the same project workflow from a terminal or a
  native desktop package.
- **HTTP API** — connect editors, internal tools, and automation to a local
  OpenCtrlC server.
- **JavaScript SDK** — use the published `@openctrlc/sdk` package to build a
  client or integration around the API.
- **GitHub Action** — run the agent in your own repository with the repository's
  `GITHUB_TOKEN`; session sharing is opt-in and requires an external service.
- **Skills and project rules** — keep reusable instructions and tool guidance
  alongside the projects that use them.

## Community projects

There is not yet an official OpenCtrlC community directory. This page will list
projects after they have been independently verified as OpenCtrlC integrations.
Until then, the most reliable starting points are the
[GitHub repository](https://github.com/ponponon/openctrlc) and
[GitHub Discussions](https://github.com/ponponon/openctrlc/discussions).

## Submit an integration

Open a discussion or pull request with:

1. The project name and repository URL.
2. Which OpenCtrlC surface it uses: CLI, API, SDK, skills, or GitHub Action.
3. Installation instructions and the platforms you support.
4. Any required provider credentials, network access, or data handling details.

OpenCtrlC does not endorse third-party projects automatically. Review their
source, permissions, and data policy before installing them.
